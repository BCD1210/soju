Diablo II: Resurrected on Apple Silicon

Use Soju to set up the Battle.net edition of Diablo II: Resurrected on Apple Silicon. macOS 26.4 or later and your own game license are required. Online gameplay has been verified on M4 Pro / macOS 26.5; results on other setups may differ.

Updated November 10, 2026. Run soju doctor d2r before starting. On older macOS, update and restart first. Neither a Soju update nor the AVX environment setting replaces OS-side Rosetta fixes. See issue #44 for the macOS 26.0.1 hang report and follow-up.

The quick version

brew install BCD1210/soju/soju
soju install      # engine + Apple GPTK files + Battle.net
soju battlenet    # log in, install D2R inside Battle.net, press Play

That's it. The installer downloads a prebuilt GPL Wine engine and Apple's Game Porting Toolkit files (checking Apple's signature on them), and installs Battle.net with Blizzard's official installer.

Why D2R "doesn't work" on Apple Silicon

If you've tried Wine wrappers before, you probably hit one of these three walls. Each has a real, specific cause:

1. The game hangs forever at launch (~86MB RAM, 0% CPU)

D2R's loader requires AVX instructions. Rosetta 2 supports AVX, but only advertises it to a process when the undocumented environment variable ROSETTA_ADVERTISE_AVX=1 is set. Without it the loader waits forever before graphics initialization. This single variable is why CrossOver works while most free wrappers appear broken: CrossOver sets it in its launcher.

2. Battle.net shows "BLZBNTBNA00000005" (the "Oops" page)

Battle.net's Agent verifies the signature of the process connecting to it, which requires resolving a PID to a full executable path. macOS has no /proc, so this needs a macOS-specific code path that most community Wine builds don't implement. Soju's engine is built from CodeWeavers' published CrossOver sources, which do.

3. Graphics crash loops with D3DMetal

Apple's Game Porting Toolkit libraries must live in lib/external/ with the wine .so files as symlinks into it. Copying the files breaks @loader_path resolution and D3DMetal dies in an assertion loop. libd3dshared is also required for the loader to pass Rosetta at all (it registers non-native code regions), not just for graphics.

All of this is documented in depth, with logs, in the diagnosis writeup (useful even if you use a different Wine frontend).

Requirements

  • Apple Silicon Mac (M1 or newer), verified on M4 Pro
  • macOS 26.4 or newer required: a 2026 Blizzard anti-cheat update triggered a Rosetta 2 bug that Apple fixed in 26.4. On older macOS the game can stall even with everything else correct.
  • Rosetta 2 (softwareupdate --install-rosetta)
  • Your own Battle.net account and a D2R license

Step by step

  1. Install: brew install BCD1210/soju/soju (or the one-line installer)
  2. Run soju install. It downloads the engine (~350MB) and Apple's Game Porting Toolkit files, then installs Battle.net automatically (5-10 minutes).
  3. Play: double-click ~/Applications/Battle.net.app (or run soju battlenet), log in, install D2R inside the app, press Play. For offline sessions afterwards: soju d2r.

Troubleshooting

SymptomFix
Game stuck at launch, ~86MB RAM Check the macOS requirement and soju doctor d2r output first. A missing AVX setting is one possible cause; launch via soju battlenet / soju d2r.
BLZBNTBNA00000005 after login Engine problem. Make sure you're on Soju's engine, not a generic wine build.
"Failed to initialize graphics" GPTK not installed. Run soju gptk.
Typed text shows as ?? Switch the macOS input source to English (ABC) while typing in Wine windows.

Questions

Why does Diablo II: Resurrected hang at launch on an M-series Mac?

D2R's loader needs AVX instructions. Rosetta 2 supports AVX but only advertises it to a process when ROSETTA_ADVERTISE_AVX=1 is set; without it the loader waits forever at about 86 MB of memory and 0% CPU. Soju sets the variable when it starts the game. On macOS older than 26.4 the game can still stall, because of a Rosetta 2 bug Apple fixed in 26.4.

Can I play Diablo II: Resurrected on a Mac without CrossOver?

Yes. Soju is free and open source, and online play through Battle.net was verified on an M4 Pro with macOS 26.5. You need an Apple Silicon Mac, macOS 26.4 or later, your own Battle.net account and a D2R licence.

What does BLZBNTBNA00000005 mean on a Mac?

Battle.net's Agent could not verify the program connecting to it. The check needs a macOS-specific way to turn a process ID into a file path, which most community Wine builds lack. Soju's engine is built from the sources CodeWeavers publishes, which have it.

Do I need an Apple ID or the Game Porting Toolkit dmg?

No. From Soju 1.10.13 the installer downloads Apple's Game Porting Toolkit files, checks Apple's signature on them and installs them. A dmg you downloaded from Apple yourself is still used if it is mounted.
